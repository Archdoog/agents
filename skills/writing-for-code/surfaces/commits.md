# Commit Messages

Use flavored mode. Read contribution instructions and recent commits before choosing a subject format.
Use the repository's prefixes, scope names, mood, and issue-reference rules.
Do not impose Conventional Commits where the repository does not use it.

Describe the behavior or maintenance outcome in the subject.
As a fallback, keep the subject at most 72 characters. Do not impose a separate 50-character warning without a repository rule.
Use the body for the reason, constraints, or consequences that the subject cannot convey.
Do not repeat the subject or narrate each edited file.

Keep a compatibility or safety rationale when a future maintainer would need it.
Do not claim tests passed unless you ran them. Mention verification only where useful or required by convention.
Avoid generated footers unless repository policy or the user requires them.
