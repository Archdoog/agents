# Issues

Use flavored mode. Read the repository's issue templates, terminology, and accepted issue examples.
Use the existing fields and workflow instead of imposing a new format.

For a bug, state observed behavior, expected behavior, environment, and reproducible steps.
Include exact diagnostics where safe. Remove credentials and personal data before publication.
Separate a suspected cause from an established cause.

For a feature, describe the reader's problem and the intended behavior.
State scope limits that prevent an unrelated solution.
Give observable completion conditions that another person can check.
Prefer "Reject an empty destination before writing files" over "Improve validation."

Keep constraints and examples needed to implement the change correctly.
Do not invent severity, affected versions, reproduction results, or user impact.
Avoid prescribing an implementation unless a verified constraint requires it.
