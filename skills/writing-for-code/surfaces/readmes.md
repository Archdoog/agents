# READMEs

Use flavored mode. Write for someone deciding whether to use the project and how to start.
Follow an existing template before this default order:

1. State the purpose and the problem the project solves.
2. Give installation requirements and commands.
3. Show the smallest real use with its expected result.
4. Link to deeper guides, API reference, contribution instructions, and license information.

Make examples runnable from the stated starting directory and environment.
Include required imports, configuration, and files. Mark placeholders clearly.
Warn before destructive commands. Do not include working credentials or private data.

Test commands when feasible. Distinguish tested commands from examples checked only against code.

Keep limitations that affect adoption or safe use. Remove promotional claims and feature lists that repeat the example.
Keep background that a new user needs, even if maintainers already know it.
Leave badges, images, and HTML presentation blocks unchanged during prose pruning.
Request the fresh-eyes review in [PRUNE.md](../PRUNE.md) before publication.
